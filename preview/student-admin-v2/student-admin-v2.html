v2 · 依据「不要树，要可筛选条件」

学生账号 · 单页 + 筛选条件

v1 那版把年级 / 班级做成了目录树，方向错了 —— 你否得对。 年级和班级本来就该是筛选条件，不是要一层层点进去的目录。 v2 只有一个页面：一排条件自由组合，选什么看什么。 导入、批次、毕业清理不再各占一屏，改成页内按钮和弹层。

一、v2 的三条硬规则

1
条件按「从粗到细」排，一律可组合、可单独摘掉
年级 → 班级 → 启用状态 → 激活状态 → 导入批次 → 关键字。 前五个是下拉，最后一个是输入框。生效中的条件会额外在下面汇总成一行胶囊 （2023 级 ✕ 01 班 ✕ 未激活 ✕）， 可以只摘掉其中一个，也可以一键「重置」。
2
班级的选项来自「当前选中的年级」，不再来自任何访问痕迹
没选年级 → 班级条件是禁用的，写着「先选年级」；选了 2023 级 → 只列 2023 级的 7 个班； 把年级改掉 → 班级自动清空。
v1 里那个 bug（classOptions 取自 gradeInfo?.classes， 取决于你上一次打开过哪个年级详情）从根上没有了 —— 班级只认年级这个条件本身。
3
批量操作的基准是「筛选结果」，不是「筛选 + 勾选」两套语义
没勾选 → 按钮文案是「重置筛选出的 7 个密码」；勾了 3 个 → 变成「重置选中的 3 个」。 一个入口，一种语义，跟着当前范围走。v1 里那个「工具栏按范围、批量条按 ids」的两套入口没有了。
4
毕业清理由「年级条件」派生，而不是藏在别的页签里
整届操作必须绑定一个明确年级 —— 所以它只在年级条件被选中时出现， 出现在结果区右上角（导出本届 / 毕业清理）。没选年级时它压根不存在，不会误点。

三、和旧版的差别

维度旧（页签 + 两个下拉）v2（单页 + 条件条）
年级 / 班级两个独立下拉，班级选项取决于上次打开过的年级详情 级联的两个条件：没选年级班级不可用；改年级班级自动清空
年级详情 / 清理回执两个隐形页签，页签条零高亮 不再是页面。年级详情 = 结果区上方的汇总条；清理回执 = 清理完成后的一次弹层
模块边界4 个页签挤在一个菜单项里 一个页面 + 三个弹层（导入 / 批次 / 清理），菜单项还是一个
批量重置密码两套入口两套语义 一个入口，跟随当前范围（勾选优先，否则整个筛选结果）
位置感共用 /student 条件全在 query 里，刷新 / 后退 / 分享可用

四、改动清单

前端重写 views/StudentAccounts.vue：页签与年级详情整段删掉， 换成「筛选条件条 + 结果表 + 三个弹层」。建议顺带拆出 components/StudentFilterBar.vue 与 views/student/ImportSheet.vue、BatchSheet.vue、PurgeSheet.vue。 路由仍是单条 /student（条件走 query，不新增子路由）。
后端0 改动。/student/list 已经支持 keyword / grade / classNo / state / activated / batch 全部条件 + 分页， 正好就是这一排筛选。唯一可选：给 /student/list 的返回加一个 facets（各级人数），用来在下拉里显示「2023 级 · 312」这种计数。
