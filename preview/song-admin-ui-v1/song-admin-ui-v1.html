点歌设置重新设计

现在 8 个板块平铺直下、说明文字和输入框混在一起、4 个保存按钮各在一处。重排为 5 个分组 + 统一保存状态。

改了什么（6 条）

1 页首加「一个播出周期」时间线 收歌周与播出周是两条不同的时间轴，页面上到处出现"周"却从不说明是哪一个。新增一条总览，把「收歌周六 18:00 → 周日 18:00」「审核截止 周日 20:00」「周一~周五 × 3 场」按顺序串起来，进页面先看到全貌，再去改局部。
2 删掉三段已经不成立的说明文字 ① 容量卡里「学生提交即占位：格子满了就进全局候补队列…全部格子占满时整个候补队列由系统自动驳回」—— 这是 v2 口径，协议版提交时完全不判容量，一律先落待审核，能不能排上是审核通过后才算的。
② 「学生提交被拦下时看到的是」里的 40906 这个时段已经排满了、40904 时段和候补队列都满了 —— 这两个码在协议版已无任何生产路径抛出，只剩 response.js 里的常量定义。
③ 该卡括号里写死的「每周六 18:00 – 周日 18:00」—— 现在窗口可配，写死的时刻会跟实际不符。
3 8 个平铺板块 → 5 个分组，按「一次点歌要经过什么」排列 收歌与审核（什么时候能点 / 能点几首）→ 排期（审核通过后谁能排上）→ 播出安排（播在哪几天哪几场）→ 学生端文案 → 危险区。每组带一句人话副标题。
4 保存按钮状态化：每个卡右侧显示「已保存 / 有未保存的改动」 现在 4 个保存按钮分散在 4 个卡里，改完两处再挨个找按钮容易漏。提案在每个卡的头部右侧固定一个保存位：没改动是绿色「已保存 ✓」，一改动就变琥珀「有未保存的改动」，按钮始终可点（不清空你的操作习惯）。
5 说明文字与输入区分离，统一收进卡底「提示条」 羊皮纸底色的一整条，视觉上明确"这段不是给你填的"。现在说明是裸文字直接跟在输入控件后面，读起来分不清哪句是规则、哪句是操作提示。
6 容量卡：统计与编辑分区 上半 4 格只读统计（正式位 / 已占位 / 候补 / 补位待审），一条分隔线，下半才是两个输入框 + 动作按钮。现在两者混在一个卡里靠间距区分。
