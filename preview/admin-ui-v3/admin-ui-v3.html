管理后台 UI 方案 v3

不改任何代码，先把后台的视觉语言对齐到小程序 v2 设计系统。核心动作只有一句话：把后台的「青蓝渐变 + 玻璃拟态」换成小程序的「单一强调色 + 羊皮纸 + 深色卡」。

本页是设计参考 + 规范。你已说明后台界面自行完成，因此这里的规范不会被主动写进 admin-web 代码，仅作为对齐依据留档。

三条硬规则（直接沿用 app.wxss）

  1. 全局只有一个强调色 #0066CC，所有「可点」的东西都用它；深色底上用 #2997FF。删除现有青蓝渐变与彩色投影。
  2. 不用装饰性渐变、不用彩色投影。投影只允许中性黑（rgba(0,0,0,·)），或不给。
  3. 深色卡是视觉主角（#272729），其余信息一律退到羊皮纸 #F5F5F7 上。

选中态 vs 可点态（关键区分）

小程序里其实有两套「高亮」，后台必须原样继承，否则会花：

  • 选中 / 当前 → 墨黑 #1D1D1F 胶囊（来自 tabBar 指示器、.filter.on）。侧栏当前菜单、筛选胶囊选中、分段控件文字都用它。
  • 可点 / 主操作 → 强调色 #0066CC（按钮、链接、开关 ON、复选框选中）。
  • 结果：一屏里彩色元素极少，视线自动落在深色卡和主按钮上。

需要你拍板的 3 个问题

  1. 深色卡放多少？本版在每屏都留了一块深色卡（概览＝直播卡、列表页＝数据带、开关页＝危险操作提示）。如果你更想要「后台尽量素、深色只出现在概览页」，我可以出 v2 收敛版。

Typography & Spacing Standard

规范 · 字体 / 行距 / 间距

这是改界面之前先看这一页的标准。所有取值都已做成 CSS 变量放在 v3 文件顶部的 :root 里， 改一处就全局生效，不需要满文件搜 font-size。

适用范围：后台界面本身。本预览的说明页（方案说明 / 规范 / 数据来源）属于文档版式，另有自己的字号，不参与这套产品规范。

1 · 字体栈（顺序不可打乱）

-apple-system, BlinkMacSystemFont, "SF Pro Text", "Inter", "HarmonyOS Sans SC", "MiSans", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif

三件事必须知道：
① 中文字体放英文后面 —— 英文用 SF Pro / Inter，中文落到鸿蒙 / MiSans / 思源，字形才统一；
② 雅黑排在最后 —— Windows 上没苹方，雅黑小字号发闷，前面几款在开发机上装了就轮不到它；
③ 数字一律 font-variant-numeric: tabular-nums（页面里是 .num 类）， 否则表格里每行数字宽度不一样，右对齐会参差。

3 · 行高规则（怎么给行高，不靠感觉）

场景行高做法
单行控件
按钮 / 标签 / 胶囊 / 输入框		 1 定高 + flex 居中，不要上下 padding 撑高。写了 padding 会让高度随字号漂移
表格单元 --lh-md 1.5 行高 1.5 + 单元 padding 13px 14px → 单行约 54px，两行约 72px，行距稳定
正文 / 说明 1.5 中文小字号的最优区间就是 1.5，不要再加大（会散）也不要 1.4（会挤）
标题 1.25 ~ 1.35 字号越大行高越小：26px 用 1.25，19px 用 1.3，17px 用 1.35
数据大字 1.15 纯数字无需呼吸空间，给最小值让数字块紧凑
长文本
公告正文 / 留言内容		 --lh-read 1.7 超过 3 行的阅读型文本唯一例外，1.7 才不累眼

硬规则：行高一律写无单位倍数（1.5），不要写 21px。 写倍数时字号改了行高自动跟着走，写死 px 就会出现「改了字号但行距没变」的错位。 唯一的例外是单行控件的中垂（用 line-height:1 + flex）。

4 · 字距与标点

  • 小字号中文必须加正字距：11.5~12.5px 用 +0.3px，表头/标签用 +0.5px。不加会显挤。
  • 大字号加负字距：17px 用 -0.4px，26px 用 -0.6px，30px 数字用 -0.8px。
  • 中文标点用全角（，。：；？！），省略号用 ……（两个字符），不用单个 …。
  • 中文间隔号 · 两边不加空格（招聘网 · 招新），但中文与数字之间要加空格（投稿 3 条）。
  • 数字与字母用等宽数字，见第 1 节 ③。

Data Source & Backend Impact

数据来源与后端改动

逐块、逐字段核对后端到底给不给得出。结论分三种，页面上也用同名角标标了出来： 现有接口 直接能拿 · 前端可推导 不用改后端 · 需后端新增 现在拿不到。

核对方式：逐条读 src/routes、src/controllers/admin、src/models 与 sql/schema.sql，以表结构为准。

先说结论

能直接支撑的：投稿与留言的完整审核流（含审核人、审核时间、批量操作）、公告与节目的增删改查与显隐置顶、 社干 / 部员 CRUD、管理员账号管理（角色 / 状态 / 最近登录）、设置与开关读写（开关能看到最后修改人）、 四组概览数字与两张图表 —— 字段名与表结构完全对得上，UI 可以照着画。

必须删掉或补后端的（v3 已在页面上打角标）： 公告阅读次数、公告草稿态、管理员头像、节目业务状态（待确认 / 已排期 / 已播出）、节目已排点歌数、 开关操作日志、留言敏感词命中标记、投稿人的年级班级。

容易误判的两个「半个字段」： ① 公告发布人 / 投稿审核人，表里只有 id，接口没 join 姓名，直接渲染会是空； ② 留言有 program_id 但没有节目名，要前端自己关联或后端补 join。 另外 admin/upload/avatar 的控制器写了但路由没挂载，实际调不通。
