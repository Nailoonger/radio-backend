这一版的规矩

入口位置列表卡最后一行「＋ 新建社团」，跟上面几行同高、同一张卡。不另起一个按钮 —— 加社团和看社团是同一件事的上下两步；也避开了「手机里挂装饰性描边框」那条。
为什么只问名称「负责人 / 指导老师」在编辑页本来就能改，且都不影响密钥。新建时多问一句就是多一道坎。
名称不可改库里的 _id 是 club:<社团名>（当年为了防并发重复插同一家）。重名直接被 _id 撞住，所以：输入时做重名提示，提交撞了回 409「已经有这家社团了」。要能改名就得先拆主键，这一版不碰。
创建即发钥匙一次 POST 建社团 + 生成首把密钥（status=1），响应里带 plain 与 shareText —— 新钥匙的第一次，与 reset 同一口径。不拆成两次请求：拆了就有「建好了但没钥匙」的半截状态。
谁看得见这一行只有超管。社干即便被勾了 clubkey 位，也只有看 / 重置 / 作废 —— 多一家社团会出现在全校学生的轮播里，这不是密钥操作，是增减组织。
后端要加什么POST /partner/club-keys body {name, ownerName?, teacherName?} → {record, plain, mask, shareText}；asSuperAdmin 闸；名称 trim 后 2~12 字、查重；_id=club:<名> + nextId；不新增集合，还是 club_keys 一张表。前端 pages-partner/club-keys/create 一个表单页 + 列表一行。
