周日 0 点切下周 · 逐页影响 v1

陛下原话：「每周周一零点到周六 24 点为可排时间填写的时间段……班表更新时间为周日晚上 0 点，即可查看最新周班表」。 落地口径就一句：周日 00:00 起，「本周」自动变成明天开始的那一周。改动只有一处 （_kit.js#currentWeekStart() → bj.dutyWeekStart()），但它管着全站五六个页面的默认周， 所以下面把每一页挨个过一遍。

切点长什么样（以 2026 年 11 月这一周为例）

周六 11/07 23:59
11/02 – 11/06 本周
还是旧周。点周六那一格的考勤、看这张班表，都还是 11/02。
00:00 切
周日 11/08 00:00
11/09 – 11/13 本周
立刻变成下周。班表周日 0 点更新，这时候点开就能看到新一周；想补看旧周用「‹ 上一周」。

逐页核对（8 个页面 / 接口）

页面周从哪来周日 0 点之后会怎样
考勤不传 week → 服务端显示新一周（周一~周五）。周六那天的考勤要补，点「‹ 上一周」回去点。默认选中「今天」那格，周日落在周一。
请假不传 week → 服务端能直接给「明天（周一）」请假。以前周日打开是上一周，得手动翻一格才能请下周的假。
排班工作台服务端 weekStart打开就是新一周的草稿，正好是周日定稿那一刻。generate 的「这一周已经过去了」判据不变。
我的班表服务端 weekStart周日 0 点起显示新一周（已发布的话）。站员周日打开看到的就是下周自己的班。
大白卡/partner/schedule/mine「本周 N 个班次」跟着变成新一周。四态（已发布 / 草稿 / 撤回 / 未生成）口径不变。
值班时间代录nextWeekStart（下一个周一）不受影响：周一到周日算出来永远是同一个答案。周日它正好等于「本周」，所以胶囊那天写「本周」而不是「下一周」，跟其它页一致。
值班时段服务端 weekStart顶部「第 N 周 10/26 – 10/30」跟着新周走（原来是小程序端 getDay() 自己算）。
意见反馈服务端 weekStart反馈挂到新一周的场次上（原来周日会挂到上一周，评错场）。

顺带清掉的「前端自己算周一」

  • 考勤 / 请假：原来各有 mondayOf(offset)，用 new Date().getDay() 推周一。 现在 offset=0 一律不传 week，让云函数给；翻周以服务端回的 weekStart 为基准 ±7 天。
  • 值班时段 / 意见反馈：同样删掉本地推周一，改读接口返回的 weekStart。
  • 保留的 getDay()：只有考勤「默认选中今天那一格」这种当场判断——那不是算周，不算违例。
  • 守卫：verify-partner-weeknav.js 新增三条 —— 分包里不许再有 mondayOf、 考勤/请假首次加载必须不传 week、可排时间默认周不许回退到本周。
