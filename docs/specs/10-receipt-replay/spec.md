# 点歌回执返回入口 Spec

## 背景
用户已于 2026-10-01 确认 `preview/receipt-replay-v1/index.html` 的方案并要求开始实现。点歌成功后停留在回执页，目前缺少继续点歌入口，切换页面再返回时旧回执仍保留。本文件记录已批准的方案。

## 目标
- 在点歌成功后提供清晰的回执和符合实际剩余次数的继续点歌入口。
- 返回投稿页时展示干净表单，撤销后的次数及时刷新。

## 功能需求
- F1：回执顶部使用与已确认预览一致的圆角线条 SVG 勾，保留浅蓝圆底。
<!-- review-fix: ISSUE-1 -->
- F2：提交成功后，根据服务端最新个人周额度决定是否显示「再点一首」：上限和已用次数必须是非负整数；上限为 0 表示不限次数，不要求提供剩余次数，显示入口；有限次数要求剩余为不超过上限的非负整数，剩余大于 0 时显示，剩余为 0 时隐藏。请求失败或不满足上述条件时保留成功回执并隐藏继续入口，不从提示文案或提交前次数推算。
- F3：点击「再点一首」后清除回执、歌名、歌手、祝福语、首选时段和时段选择标记，回到点歌表单顶部，重新获取次数、时段、窗口和注意事项。调剂开关恢复默认开启。
- F4：切到其他页再返回投稿页时，若保留了成功回执，按 F3 清理并刷新；未提交的点歌草稿和文稿草稿继续保留。
- F5：保留「查看我的投稿」及审核、统一排期说明。慢请求不得让已离开的回执重新出现，也不得把旧额度覆盖到新一次回执。

## 非功能需求
- N1：复用现有点歌接口和设计系统，无新增依赖或数据库迁移。
- N2：额度请求失败不影响提交成功反馈；SVG 通过小程序支持的图片方式显示，图标不依赖字体。

## 不做的事
- 不变更后端审核、周限额、撤销和排期规则，不修改管理员界面。
- 不把预览中的「新增」注释标签或演示日期写入正式页面。
- 不重做整个回执卡片、导航或其他页面，不改文稿提交流程。

## 验收标准
- AC1（F1）：成功回执显示圆端点、圆拐角的蓝色 SVG 勾，图标尺寸与已确认预览比例一致。
- AC2（F2）：服务端返回上限 2、剩余 1 时显示继续入口和剩余提示；上限 1、剩余 0 时隐藏入口；上限 0 时显示入口。
<!-- review-fix: ISSUE-1 -->
- AC3（F2、N2）：成功后的额度请求失败，上限或已用次数缺失、为负数或非整数，或有限次数的剩余缺失、为负数、非整数、超过上限时，仍显示成功回执，隐藏继续入口和未知剩余提示。不限次数的剩余为空或缺失时仍能继续。
- AC4（F3）：点击继续入口后显示空点歌表单，原时段无选中标记，页面回到顶部并刷新前置数据。
- AC5（F4）：在「我的投稿」撤销后返回投稿页，回执消失、表单清空、次数由服务端刷新；普通切页返回同样清理回执。
- AC6（F4）：尚未成功提交时切页再回来，点歌草稿和文稿草稿保留。
- AC7（F5）：新回执只应用提交成功后最新一次额度响应；旧请求晚返回不改变当前回执，离页期间提交成功不在返回时恢复旧回执。
- AC8（F5）：「查看我的投稿」跳转正确，现有审核和排期说明保留。
