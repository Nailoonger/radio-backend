# 全项目 Git 版本管理与云端自动发布 Spec

## 背景

项目已经使用同一个 GitHub 仓库管理后端、管理后台、小程序、云函数与部署资料，生产分支为 master。目前管理后台靠人工上传静态文件，云函数靠人工部署，推送代码不会同步更新线上版本。

仓库检查发现，两个被管理接口依赖的正式云函数源码被临时文件忽略规则排除；数据库备份、用户上传文件和小程序私人配置已有文件被跟踪。发布流程必须先保证从仓库重新获取的源码完整。

## 目标

- 全部业务源码、测试、依赖清单、数据库结构、部署资料和设计源文件由现有仓库统一记录版本。
- 推送生产分支后，管理后台和云函数按实际变更自动校验、构建并发布。
- 每次发布关联明确的提交版本，失败可定位，旧版本可重新发布。

## 功能需求

- F1：补齐漏跟踪的正式源码；新增设计源文件和其必要资源纳入版本，已记录的设计资料继续保留。发布校验至少覆盖管理后台构建、全部云函数业务模块及依赖加载、学生与管理员鉴权、点歌提交约束、点歌审核与清空的权限边界、小程序源码语法。云函数校验同时覆盖源码与从该源码重新生成的产物，避免仅因本机缓存或旧产物而可运行。
- F2：本地环境密钥、私人配置、运行数据、数据库备份、依赖目录与临时构建产物不进入后续提交。已跟踪的运行数据和私人配置停止跟踪并保留本地副本；本轮不改写既有提交历史。
- F3：拉取请求执行校验但不发布；生产分支推送仅发布发生变更的管理后台或云函数。仅修改文档、设计预览、归档后端或数据库结构时，不自动改变线上服务或业务数据。
- F4：同一提交同时修改云函数和管理后台时，相关校验全部通过后，先更新云函数并确认服务健康，再发布管理后台；任一前置步骤失败，后续发布停止。只修改其中一端时，只发布该端。
- F5：更新现有云函数时保留原有运行配置、环境密钥、定时触发器和接口入口；部署前后检查保留结果。配置发生差异时不得报告成功，不输出密钥值。
- F6：管理后台继续使用当前云端环境和现有访问地址，保持页面刷新时的路由回退规则。云通道地址在构建时明确提供；缺少配置直接失败。
<!-- review-fix: R1-S3-01 -->
- F7：每次校验和发布显示关联提交、各阶段状态与失败原因；允许用户通过新增回退提交恢复生产分支中指定历史版本的业务代码，保留当前发布机制、运行配置和业务数据。回退提交按新的生产分支提交走同一自动发布流程，不直接把旧提交插入发布队列，不改写历史。
- F8：小程序业务源码统一记录版本并执行源码校验；正式版上传、审核与上线沿用微信发布流程。本轮不增加小程序自动上线。
- F9：提供一次性启用说明，列出需要在 GitHub 保存的发布凭据和非敏感配置。凭据由用户在平台中设置；未完成设置时明确失败，不伪称自动发布已启用。已有其他发布触发器须在启用新流程时停止，以免重复发布。

## 非功能需求

- N1：同一生产环境最多执行一条发布流程；进行中的发布不被后来的推送中途打断，等待中的旧提交不得覆盖较新的线上版本。
- N2：F1 规定的最低发布校验必须全部通过才能上线；校验在隔离的本地数据环境中执行，不读写生产学生数据。归档后端既有失败测试单独报告，不以忽略所有失败替代发布校验。
- N3：发布日志、构建产物和 Git 提交中不得包含云平台密钥、应用密钥或生产密码；部署凭据仅用于生产分支的发布步骤，拉取请求的校验步骤不读取部署凭据。
- N4：失败日志保留可操作的阶段信息；发布准备、校验与发布流程的总执行上限为 30 分钟，超时判为失败。
- N5：流程实施以管理后台和现有网关云函数为一个开发周期；对初次启用需要的平台账号授权和凭据配置明确标注为外部步骤。

## 不做的事

- 不迁移、删除或重建云数据库，不自动执行数据迁移，不改变业务规则。
- 不重新发布旧服务器上的 Docker 服务，不拆分现有 Git 仓库。
- 不自动审核或发布微信小程序正式版，不新增付费托管服务。
- 不重写已有 Git 历史，不删除本地运行数据、私人配置或现有设计资料。
- 不为了发布流程扩展业务功能，或统一修复归档后端的全部历史测试。

## 验收标准

- AC1（F1）：在只包含仓库跟踪文件的独立目录安装依赖后，管理后台能构建，全部云函数业务模块及依赖可加载；云函数源码和重新生成的产物均通过鉴权、点歌约束、审核与清空权限回归，小程序源码语法校验通过；正式源码无遗漏。
- AC2（F2）：新建本地环境配置、私人配置、上传文件和数据库备份后，Git 待提交列表不出现这些文件；既有文件停止跟踪后本地副本仍存在。
- AC3（F3、F8）：拉取请求可见校验结果且无生产发布；分别修改网页、云函数、小程序源码或文档时，只有对应的发布或校验步骤被执行。
- AC4（F4）：同时修改网页和云函数时，发布记录显示云函数健康检查先于网页发布；人为制造校验失败或云函数发布失败后，网页发布没有执行。
- AC5（F5）：在现有云环境验证一次代码发布，部署前后的环境配置和触发器保持一致，原有接口入口可用，日志中不出现密钥值。
- AC6（F6）：用原管理后台网址打开、登录并刷新后台子页面成功；缺少云通道构建配置时流程失败，未发布错误通道的网页。
- AC7（F7）：发布记录显示具体提交；选择一个已发布的业务版本并创建新的回退提交后，该业务代码可通过新的自动发布重新上线，发布机制、业务数据和当前运行配置不被回退；该回退提交按新提交顺序执行。
- AC8（F9）：按说明配置发布凭据和非敏感变量后，生产分支推送自动产生发布记录；缺少凭据时明确报出缺项，其他发布入口没有并行重复部署。
- AC9（N1、N4）：连续提交触发的发布不会并行写入同一环境，完成顺序不会使旧提交覆盖新提交；总流程超过 30 分钟时停止并显示超时状态。
- AC10（N2、N3）：测试失败阻止发布，拉取请求无需部署凭据即可执行校验；检查日志和构建产物未包含生产密钥或学生数据。

## 外部依赖与当前状态

- 需求范围：用户已选择“统一版本管理＋自动发布”。
- 审查策略：用户已选择单轮审查。
- 生产平台：已有云开发环境、静态网站托管和网关云函数。
- 启用条件：用户完成 GitHub 发布凭据与变量设置后，才能验证首次线上自动发布。
- 本文档状态：单轮独立审查发现 2 处 major，已修正；用户于 2026-09-30 明确批准“按这个方案做”。
