# 原生伙伴端班表对齐 v151

依据用户 2026-10-29「把 151 方案的班表落地到小程序上」及既有班表要求执行。视觉与交互来源为本地 v151 定稿，继续采用已批准的一页多角色、真实接口与无权重排班方案。

## 需求与验收

- F1 / AC1：班表主导航先展示本周正式安排；未发布明确显示「本周未发布」。课程表按周一至周五排列，周一早会独立横带置顶，多部门需求分别展示，无排班也保留真实时段的空缺位置。
- F2 / AC2：社干、超管从班表下方进入排班工作台。工作台包含班表、状态、生成、检查、发布、清空与岗位换人，并可查看时段、规则、代录和记录。站员无管理操作。
- F3 / AC3：生成与人工调整均满足时段、已确认可排时间、岗位资格、请假、冲突、每天及每周上限。无合适人员保留缺岗，并显示原因；固定的人工安排在再次生成时保留。
- F4 / AC4：发布须由服务端重新检查。存在硬条件冲突不可发布；缺岗需明确确认后发布。已发布不可直接改，超管可撤回，保留原有人选，修改后再次发布递增版本。
- F5 / AC5：轮值页仅统计已发布正式周的真实月度场次；记录页展示操作者、时间、原因、版本，撤回历史快照仅超管可见。空列表和接口失败明确区分。<!-- review-fix: ISSUE-2 -->
- F6 / AC6：社干和超管按实际岗位资格参与个人排班，具有本人请假与可排时间入口。导航从现有小程序胶囊进入，二级页不叠加主胶囊。

## 边界

仅涉及原生班表及必要云函数，不修改「我的」背景、登录、审核或其他业务界面。不植入原型演示身份、人数或假班表。不新增个人权重。手机导出继续提供明确标注的文本复制，不冒充 Excel 文件。上线发布不包含在本地代码验收中。

## 非功能要求

北京时间以服务端返回的本周起点为准；请求失败不可伪装成未发布。编辑和发布必须检查草稿修订号，过期页面不得覆盖他人更新。<!-- review-fix: ISSUE-1 --> 原生模板与样式通过微信编译器检查，数据规则用真实 handler 的隔离测试校验，页面事件用小程序运行环境替身验证。
