# 原生班表实现计划

1. 复用 `adminRequest`、admin 独立登录态与原生伙伴胶囊。新增共用 `schedule/timetable` 组件，将服务端 `days[].slots[].groups[]` 映射为独立单日横带和多日课程表；同一时段按部门及岗位分组，使用 slotKey 编辑，不凭标题定位。
2. `schedule/index` 负责正式查看与管理入口，`schedule/planning` 承担编辑流程、候选人弹层、缺岗及检查结果。请求服务端时首次不传 week，采用返回的 weekStart，后续操作固定该周。已有页面回到前台重新加载。
3. 新增 `schedule/workload`、`schedule/history` 原生页，注册分包路由。辅助页复用真实月度和记录接口，无占位 toast。
4. 扩展现有 schedule handler：模板和已排人员合并读取、资格检查、候选解释、发布二次校验、超管撤回保留数据、按格调整、清空草稿、版本日志。写操作提交草稿 revision，旧修订号冲突须刷新，按周数据库租约防止并发覆盖；草稿单独存储，正式人员只在发布时写入，撤回后正式业务读取须检查周状态。<!-- review-fix: ISSUE-1 --> 月份只统计已发布周，撤回版本快照仅超管可见。<!-- review-fix: ISSUE-2 --> 扩展 schedule 契约并保持字段兼容。相同起止时间的不同部门岗位允许并行；不可重复同一需求，禁止其他重叠。
5. 原生 `slots` 页面同步并行需求校验，避免客户端把合法多部门需求拦住。班表管理只读首页保留 v151 四项入口，时段与规则统一收在工作台。
6. 验证：微信 wcc/wcsc、Node 语法检查、页面事件与路由验证、云端真实 handler 生命周期/权限/多部门/固定安排/请假/发布/撤回/再发布测试，运行现有伙伴测试与接口契约检查。不得改写或清空真实云数据。
