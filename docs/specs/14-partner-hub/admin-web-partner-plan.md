## 0. 先说清身份对应（陛下 2026-10-29 补充口径）

| 伙伴端角色 | 账号表 | role | 对应电脑端 |
|---|---|---|---|
| 超管 | `admin` | 0 | admin-web 超管（现有） |
| 社干 | `admin` | 1 | **admin-web 普通管理员**（现有） |
| 站员 | `admin` | 2 | 电脑端**不登录** admin-web，只在伙伴端用（新增角色） |

⚠️ 站员那一行用 `admin.userId` 指回 `user`（学生档案），排班表里的 `personId` 仍用 `admin.id`。
也就是说：**站员既有学号档案，又有一条伙伴身份**，两者靠 `userId` 挂在一起。

## 2. 方案：新增一组菜单「伙伴端」

在「内容运营」「系统管理」之间插一组，**仅超管 + 社干可见**（站员不进电脑端）：

```
伙伴端
├── 伙伴账号        ← 陛下点名：账号管理里加「站员」模块
├── 值班时段
├── 排班规则        （仅超管）
├── 班表            （周视图 / 生成 / 校验 / 发布 / 撤回）
├── 可排时间        （汇总 + 代录）
├── 请假审批
├── 考勤            （点名 + 总览）
├── 站内稿件        （审稿）
└── 互评            （只读统计，不做"谁评谁"明细）
```

### 2.1 伙伴账号（优先级最高）

**陛下原话**：*「账号管理的那里加一个站员的模块，我后续在那里导入站员信息」*

两种落法，**要陛下选**：

| | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A** | 在现有「账号管理」页里加一个「**站员**」分段（现有是"管理员账号"列表） | 不新增菜单，账号都在一起 | 一页管内两种角色，页会变长 |
| **B** | 独立一页「伙伴账号」，页内三段：超管+社干 / 站员 / 待加入（从学生名册拉人） | 角色边界清楚，导入有专门的地方 | 账号管理变成两处入口 |

**我建议 B**（小程序端已经有「伙伴账号 / 待加入」两段，电脑端照这个结构对齐最省心）。

**站员导入要做的事**（两种输入都要）：
1. **从学生名册勾选**（`user` 表已有的人，逐条建 `admin` role=2 + `userId`）；
2. **Excel 粘贴/上传**（只有学号+姓名，系统去 `user` 表核对；对不上的列出来让人确认，不静默跳过）。

导入结果必须回一张表：`成功 N 人 / 跳过 M 人（原因）/ 学号不存在 K 人`。

### 2.2 班表（电脑端最该有的）

周视图（照小程序 `.wk` 那套：早会横带 + 5 列网格 + 人名胶囊），外加：

- **生成草稿**（同一套算法，服务端跑）
- **手动换人**（点格子换人：给候选列表，标出「为什么可选/不可选」——没填可排、已请假、超上限）
- **校验**（缺岗清单 + 原因）
- **发布 / 撤回**
- **导出 Excel**（电脑端可以真出文件，不像手机端只能复制文本）

## 3. UI 口径（这里必须陛下定，我不敢猜）

现在 admin-web 用的是另一套设计语言（Element Plus + 青蓝渐变 + 玻璃拟态 `theme.css`），
跟小程序伙伴端（羊皮纸底 + 白卡 + `#0066CC`）**是相反的两套**。

陛下说*「账号那个模块你给我按照方案 ui 做不要改」*，有三种理解：

| | 做法 | 结果 |
|---|---|---|
| **① 照 v151 手机端的样子做** | 伙伴端这组页面用 `#F5F5F7` 底 + 白卡 + 胶囊，不复用 Element 表格 | 跟小程序高度一致，但和 admin-web 其它页不像同一套系统 |
| **② 用 admin-web 现有样子做** | Element 表格 + 现有侧栏风格 | 后台统一，但和 v151 方案长得不一样 |
| **③ 混：布局用 admin-web，组件用 v151 的胶囊/卡片** | 例如账号列表还是表格，但状态标签、胶囊按钮照 v151 | 折中，最容易两边都不像 |

**我推荐 ①，但只在「伙伴端」这一组内生效**，其它页不动——理由是伙伴端管理强调的是和小程序一致（同一批人在用）。
