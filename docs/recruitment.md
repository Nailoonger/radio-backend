# 招新模块运维与验收

需求与技术设计见 `docs/specs/12-recruitment/`。

## 使用流程

1. 超级管理员在 Web 后台「招新管理」建立批次，填写介绍、报名起止时间和自定义问题，保存草稿后发布。题目发布后锁定。
2. 学生在小程序「我的 → 加入我们」公开报名。姓名、学号、年级、班级必填，不要求学生账号登录。介绍及表单提示「仅限高一、初一学生报名」，服务端不做身份和年级验证。
3. 提交成功后保存随机查询码；凭码在「查询报名」查看、修改或撤回，截止后只读。查询码持有人可访问报名，不能转发给他人；无姓名或学号找回入口。
4. 截止后管理员安排面试，填写内部备注、最终决定与对外说明。录取必须经过待面试；已提交可直接拟定未录取。发布前可明确撤销拟定结果，恢复未决定状态后重新安排面试或修正决定。
5. 所有有效报名有决定后，超管统一发布结果。发布前学生无法查看内部决定，发布后结果锁定；可归档，历史查询继续有效。

## 云环境前置条件

- 本期新增功能只走云函数 `api`，Web 后台需配置 `VITE_REQUEST_MODE=cloud` 和现有 `VITE_CLOUD_API_URL`。小程序沿用当前 cloud 请求模式。直连 Express 后端未新增招新接口。
- 云函数环境变量 `RECRUITMENT_CODE_KEY` 必须为密码学随机生成的 **32 字节密钥、64 位十六进制文本**。在云控制台或受控密钥管理中设置，不提交仓库、不打印到日志。上线后保留该密钥，随意替换会使响应丢失后的原提交重试无法解密原查询码。
- 依照 `cloud/scripts/init-recruitment.js` 创建新增集合；初始化脚本只做加法，不改学生名册、点歌或旧数据库。先运行默认命令查看清单；实际运行需 `--run --env <云环境 ID>` 及管理凭据，复用 `scripts/release` 已锁定的管理 SDK。部署前运行初始化，不向外打印凭据。
- 新集合数据库权限必须设为客户端不可直接读写，只允许云函数服务端访问。查询码摘要和密文不能经客户端数据库接口暴露。
- 原生调用限流按平台注入的微信来源标识，不要求学生账号登录；HTTP 按平台注入的来源 IP 限流。用户传入的来源字段或转发头不能替代可信来源。
- 原生微信来源优先于任何事件中的 HTTP 字段，不能通过伪装 HTTP 请求或改变来源 IP 重置限流。限流过期字段为普通数值索引；现有定时器每小时清理至多 100 条过期记录，不依赖数据库 TTL。
- 发布前在开发云环境验证 SDK 的事务能力、可信来源字段及密钥配置。此项不能由内存测试代替。

## 本地验证

```powershell
node cloud/scripts/test-recruitment.js
node cloud/scripts/sync.js
node cloud/scripts/regression.js
npm --prefix admin-web run build
npx jest --runInBand
```

招新测试从真实云网关进入，检查公开报名、固定及动态字段、码查询、幂等重试、学号并发去重、撤回重新提交、时间窗口、管理员权限、面试、统一结果发布、归档及限流。内存 harness 支持序列化事务和失败回滚，不模拟真实云数据库的网络、索引、权限规则及并发锁冲突。

小程序还需在开发者工具编译 WXML，并使用真机验收题目渲染、复制码、修改撤回及北京时间显示。所有 JS 需通过 `node --check`。管理端应确认发布题目锁定、普通管理员的按钮边界与结果发布阻断状态。

## 开发环境实测清单

- 提交同学号的并发请求，只有一份报名且未决定计数为 1。
- 模拟首次提交响应丢失，同一提交重试拿回同一查询码；不同提交凭证不能拿回原码。
- 未设置密钥、数据库网络错误时拒绝创建，不能创建半份报名。
- 查询无效码或超过频率时不返回个人信息；接口异常不输出学生数据或查询码。
- 报名截止时修改/撤回失败，审核与面试此时开始允许；发布与审核并发不产生部分结果公开。
- 普管直接调用发布/归档接口被拒绝，超管统一发布后所有有效报名可凭各自码看结果。

现有 Jest 的旧 member/switch 套件需单独记录失败原因，不能用旧套件的环境或路由失败代替招新功能验收。
