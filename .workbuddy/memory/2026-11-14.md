### ② 「周锚点错位一周」：**不是算法错，是两套时间轴 + UI 不显示日期**
- 口径自洽：`anchorOf(weekStartMs)` 传 `weekStartMs − 1s` ⇒ **点播周 = 播出周 − 7 天（固定）**。
  探针实证：每一轮都是「点播周周五 02:50 → 播出前 2.88 天」⇒ **配置里的「周五」永远指点播周的周五**。
- **真正的分叉点 = 2026-11-16 00:00**（探针表四实证）：实时窗口（`status` 按 now 跳轮）过了周一 00:00
  就跳到 11-20 那轮（归属播出周 11-23），而**周行锚点按周冻结**仍钉在 11-13
  ⇒ 后台「点播周」与「播出周」两块并排显示，两个日期正好差一周。**每周一 00:00 必现一次，不是偶发。**
- 病灶在 UI：`admin-web/src/views/SongSettings.vue:73-74` 只打时刻 `hhmm(win.start)` / `hhmm(win.reviewAt)`，
  **不带日期**；「点播周」侧只写「审核截止 周五 02:50」⇒ 日期一藏，"差一周"就看不出来了。
- ⚠️ 另有真实病灶：`enabled=0` 时 `status()` 恒 `open=true`（"不限时间"），但锚点仍按配置星期算
  ⇒ **「不限时间」与「审核截止钉在某一刻」两套语义并存**。线上正是 enabled=0，
  于是这一轮（播出周 11-16）的锁定时刻 11-13 02:50 早就过了。

### ③ 「open=true vs canApply=false」：**不是功能冲突，canApply 是死字段**

### 🆕 额外挖出一条全项目级静默坑：`bj.shifted(Date)` 会丢掉 8 小时
- 机制：`Date + number` 走 **ToPrimitive(default) → Date 的 toString 先于 valueOf** ⇒ 变成**字符串拼接**，
  `new Date("...28800000")` 的宽松解析把尾巴吃掉 ⇒ 结果 = 原时刻，**+8h 静默消失**（不报错）。
  实测：`bj.ymd(bj.shifted(new Date(Date.UTC(2026,10,15,16,0,0))))` = `2026-11-15`（应为 `2026-11-16`）。
- 触发点：全仓只有 `weekdayOf(d)` 会把 Date 传进 `shifted`（`bjTime.js:89-91` / `src/utils/bjTime.js:68`）。
  而 `cloud/cloudfunctions/api/handlers/partner/_kit.js:410`「week 必须是周一」**正好传 Date**
  ⇒ **北京时间周一 00:00–07:59 之间，伙伴端提交可排时间会被误判「week 必须是周一」报 40001**。
- ✅ **点歌链路全部传 `.getTime()`，没踩这个坑**（我自己的探针第一版踩了，标签整整差一天，已改）。
- 修法（一行，云 + 源同步）：`function weekdayOf(d){ return shifted(d instanceof Date ? d.getTime() : d).getUTCDay(); }`
  或给 `shifted()` 加护栏（传 Date 直接抛错）。
- ⚠️ `cloud/scripts/selfcheck.js:88` 用 `weekdayOf(new Date(ts))` 比对云/源 —— **两边同样错 ⇒ 自检永远发现不了**。
