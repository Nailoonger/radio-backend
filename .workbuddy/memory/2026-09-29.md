## ⚠️ 抓到 1 个真 bug（只在成功路径上炸，测试不覆盖就上不了线）
`services/roster.js` 的 `commit()`：
```js
const batchId = await nextId(C.IMPORT_BATCH);
await insertOne(C.IMPORT_BATCH, { id: batchId, ... });            // _id = 'auto_7'
await updateById(C.IMPORT_BATCH, batchId, { created, updated });  // ❌ doc('1') 不存在 → 抛错
```
云文档 `_id` 是自动生成的字符串，`batchId` 是**数字业务主键**。`updateById` 走 `doc(_id)`
→ 抛 `document does not exist` → 整个 `commit` 变 50001。
**特征：写失败（40001/40901）的用例全绿，唯一没覆盖的就是「导入成功」那条。**
✅ 修：接住 `insertOne` 的返回值 `batchDocId`，用它更新。
**排查手法**（已写进 skill）：`grep -n "updateById(" | grep -v "_id"` —— 全项目 34 处只有这 1 处踩坑。

## ②B `previewSchedule(dryRun)` 归零 → 已修（比方案描述多两层）
根因其实是**两层**（方案里只写了第 1 层）：
1. `reschedule` 按**库**查候选 `scheduleStatus=WAITING` → 第一步 dryRun 没写库 → **一条都查不到** → 三个数字恒 0；
2. 各格占用也是按库算 → 第一步刚发给别人的座位在第二步眼里**仍然空着** → 同一人塞进两个位置，
   「模拟后各格占用」双计。**只修 1 会「数字对了、占用图更虚」**。
3. **第三层（最贵）**：`autoRejectedIfLocked` 原先 = 「两步合并的 waiting 动作数」，
   而锁定时刻 `lockWeek()` 是**显式 `crossSlot: true`**（点播早已截止、闸门必放开）
   → 预览说「会驳回 1 条」，真锁定是 0 条 —— **连主结论都错**（比归零更严重）。
   现在：闸门本来就是开的就复用 `b.left`；闸门关着（点播未截止）时**另跑一轮纯内存演练**取 `left`。
   ⇒ `stillWaiting`（看**现在**）与 `autoRejectedIfLocked`（看**锁定时刻**）成了两个含义不同的数字。

实现：
- `services/scheduling.js`
  - `initialAllocate({dryRun})` 额外返回 **`waitingRows`（整行）**（非 dryRun 恒空数组）。
    ⚠️ 只留 action 摘要不够：排序要 `createTime`/`id`、可接受落点要 `allowReschedule`。
  - `reschedule()` 新增 dryRun 专用入参 `extraWaiting`（内存候选，**按 id 去重**）
    与 `seatedOverride`（内存占用表，**内部 `{...}` 拷贝**，别改脏调用方的对象）。
- `handlers/admin/submit.js` `previewSchedule()`：`afterA`（落座后占用）+ `waitingRows` 交给第二步；
  `plan.waiting` **按 id 去重**（同一条可能两步都判候补 → 不去重会列两遍、计数翻倍）。

断言（`test-admin-submit.js` H 段 14 → 20 条）：
- `[promoted, rescheduled, stillWaiting]` `[0,0,0] → [0,1,0]`，并钉住调剂目标 `${DATE0} 午间 12:20`（成本表 10 档）。
- `crossSlot=false`：`stillWaiting` 1、但 `autoRejectedIfLocked` 仍 0 → 证明两数字含义不同。
- ⚠️⚠️ **反向用例（必需）**：`allowReschedule: 0`（拒绝调剂）+ 首选格满 → `autoRejectedIfLocked` 必须为 **1**。
  没有它，上面那些 `=0` 的断言用一个「恒返回 0」的坏实现也能全绿。
  → 凡「把恒 X 改成真实值」的修复，都要补「值不该是 X」的用例。`mkSubmit` 顺带支持 `allow` 覆盖 `allowReschedule`。
