## ⑦ 重要更正：`jyradio.online` **并未备案**（我先前判断错了）

陛下指出域名没备案。我原判断的依据是错的 —— **把「nginx 里配了 443 + 证书」当成「已备案」，
但证书（Let's Encrypt 等免费证书）与 ICP 备案完全无关**。记下来，别再犯。

### 实测取证（本机直连、`--noproxy '*'` 绕开本机代理）

| 探测 | 结果 |
|---|---|
| `nslookup jyradio.online` | → `129.28.26.180`（解析正确） |
| `http://jyradio.online` | **301 → https://**（80 没被拦，请求到了 nginx） |
| `https://jyradio.online` | **TLS 握手被 RST**：`curl: (35) Recv failure: Connection was reset` |
| `https://129.28.26.180`（纯 IP） | **HTTP 200**、ALPN 握手正常 |

⇒ 拦截发生在 **TLS 握手阶段（按 SNI 识别域名）**，与服务器/证书无关 = **未备案域名被拦的典型表现**。
⇒ 顺带解释了**小程序当初 `url not in domain list` 的根因**（小程序要求 request 合法域名必须已备案）。
⇒ 也说明**用域名访问现在是死的**：80 会 301 跳 https，而 https 被 RST。

### 修正后的结论

**不需要备案的只有两条**：
1. **服务器 + 纯 IP 访问** `https://129.28.26.180`（IP 不受备案限制）—— **陛下现在就是这么用的**
2. **云开发静态托管 + 腾讯云默认域名**（能停服务器；但默认域名有「访问提示中间页」、官方明文严禁生产）

**想用 `jyradio.online` ⇒ 必须备案**（备案后既可绑服务器、也可绑云开发静态托管）。
⇒ 诚实结论：不备案就没有「既免备案、又完全合规好用」的方案。

- CORS 补充：实测 `Origin: https://129.28.26.180` 与 `http://129.28.26.180` 都**不在**网关白名单，
  若走 A′ 必须去控制台「跨域设置」加 IP 这个来源。
