## ⚠️ git push 失败排查（21:45）：真凶是 ~/.gitconfig 的 **URL 级** github 代理

**现象**：`git push origin master` → `Failed to connect to github.com:443 over proxy 127.0.0.1 after 2097 ms`。
commit 本身是成功的（`f1f9d77`，42 files changed），只是没推上去。

**排查坑（别再只看环境变量 / `--get http.proxy`）**
- `git config --get http.proxy`、`--global --get http.proxy`、`--system --get http.proxy` **全是空**
  → 极易误判"没配代理"，然后往环境变量方向查半天。
- 真凶得用 `git config --list --show-origin`：
  `file:C:/Users/Administrator/.gitconfig  http.https://github.com.proxy=http://127.0.0.1:7890`
  ⚠️⚠️ 键名是 **URL 级作用域**（`http.<url>.proxy`），`--get http.proxy` **永远查不到**。
- 顺带排除掉的干扰项（都不是根因）：
  工具会话里有沙箱注入的 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:52846`（监听者 `sandbox-cli`，**不在陛下系统里**）；
  WinINET `ProxyEnable=0` 但残留 `ProxyServer=127.0.0.1:7890`（老坑）；
  FlClashCore 在跑，**但无 TUN 网卡、不监听任何端口** ⇒ 蜂窝当前根本没接管流量。

**结论（21:53 复查后修正 —— 前一轮「直连通」的判断是错的）**
- ⚠️⚠️ **绝不能删 `~/.gitconfig` 里那条 github 代理**，它是对的且必需。
- 复测证据（同一时刻两条对照）：经 `7890` → ✅ 秒回 `65d4e62 refs/heads/master`；
  把代理覆盖为空直连 → ❌ `Failed to connect to github.com:443 after 21056 ms`（21 秒超时）。
  ⇒ **github 直连不通，7890（蜂窝）是唯一通路。**
- ⇒ 真正的失败原因：**蜂窝当时没启动**。首轮探测 FlClashCore 在跑但 `7890 listen count = 0`、无 TUN 网卡；
  第二轮探测 FlClashCore 已监听 **7890**（端口代理模式，非 TUN），链路立刻恢复。
- ⇒ **push 前先确认 7890 在听**：`(Get-NetTCPConnection -LocalPort 7890 -State Listen).Count` 应为 `1`；
  然后直接 `git push origin master`（.gitconfig 已把 github 指向 7890，**不用加任何 `-c`**）。
- ⚠️ 前一轮 `git -c ...proxy=` 那次"成功"是**侥幸**（间歇性 reset 的反面），别据此下结论。
- ⚠️ 沙箱里 push **必然失败**：`could not read Username for 'https://github.com': terminal prompts disabled`
  ⇒ 凭据只在陛下本机的 GCM 里，**push 只能他敲**（老结论成立）。
- ⇒ 排查网络类问题第一刀：`git config --list --show-origin | grep -i proxy`（`--get http.proxy` 查不到 URL 级键）。
