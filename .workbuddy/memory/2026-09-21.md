**诊断（对象 = `admin-web/src/views/StudentAccounts.vue`，1617 行）**

但对象层级本来是四层：批次 → 年级 → 班级 → 账号。五条病灶：
1. `tab` 一个变量同时表示「哪个平行功能」和「按年级里的哪一层」；`switchTab('grades')` 顺手清 `gradeInfo`、`openGrade()` 又原地设回 `tab='grades'` → 返回上一级靠手写链接。

## 🐞 修 bug：管理端「改名」按钮点了没用（已修 + 已补回归）

用户报「改名的那个按钮改完之后没有实现目的」。

**根因（字段名对不上，静默 no-op）**
- 前端 `StudentAccounts.vue` 的 `submitRename` 发的是 `{ remark: x, nickname: x }`；
- 后端 `studentRosterService.updateStudent` 只读 `payload.name`（`patch.remark = payload.name`）；
- → 三个 key 全落空，接口照常回 200「已保存」，**姓名一个字都没动**。

**连带问题（就算把字段名对上，只写 remark 也不够）**
读姓名的地方不是一个，而且 `nickname` 优先：
| 读哪 | 读什么 |
|---|---|
| 管理端学生账号列表 | `remark`（dto 暴露成 `name`） |
| 管理端投稿审核 / 留言审核 | `nickname \|\| remark` |
| 小程序「我的」/ `/user/me` | `nickname \|\| remark` |
| 名册导入落库 | **两列一起写** |
所以改名必须 **`remark` 与 `nickname` 同时写**，否则管理端变了、学生端还是旧名。

**改了什么**
1. `src/services/studentRosterService.js` `updateStudent`：
   `name` / `remark` / `nickname` 三个 key 都接受（兼容旧调用方，杜绝再静默失败）；
   校验 trim 后非空（空 → 40001「姓名不能为空」）、≤64 字；**两列同时写**。
2. `admin-web/src/views/StudentAccounts.vue` `submitRename`：改发 `{ name }`，
   加空值/未变化短路，**用 try/catch 自己弹错误提示**（`utils/http.js` 的响应拦截器对
   `code!==0` 的业务错只 reject、**不弹 message**，只靠"拦截器已提示"会静默失败）。
   弹窗补上「账号 xxx · 班级」上下文 + 回车提交。
3. `scripts/verify-student-account.js` 新增 **G3 段 12 项断言**（原本这条路**一条覆盖都没有**，
   所以 bug 才能溜到线上）：name 落库、nickname 同步、列表搜得到、
   **学生端 `/user/me` 也是新名**、别名兼容、空名/超长拒绝、改状态不串字段。
   → `node scripts/verify-student-account.js` = **163 项通过 / 0 失败**。
4. `docs/student-account.md` 补「姓名的字段名」小节（读哪列的表 + 别名 + 回归位置）。
