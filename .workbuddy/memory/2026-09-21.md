## 学生账号模块「目录化」重构方案 v1（已完成，等用户拍板）

**触发**：用户说「学生账号那个模块的设计逻辑太混乱了，子目录和主目录混淆不方便管理，请你给一版新的逻辑我看看」。

**诊断（对象 = `admin-web/src/views/StudentAccounts.vue`，1617 行）**
现状是「一个页面 + 4 个平级页签（账号列表/批量导入/导入批次/按年级）+ 2 个隐形页签」，
但对象层级本来是四层：批次 → 年级 → 班级 → 账号。五条病灶：
1. `tab` 一个变量同时表示「哪个平行功能」和「按年级里的哪一层」；`switchTab('grades')` 顺手清 `gradeInfo`、`openGrade()` 又原地设回 `tab='grades'` → 返回上一级靠手写链接。
2. **`classOptions` 的来源是 `gradeInfo.value?.classes`** → 班级下拉的选项取决于「上次打开过哪个年级详情」；没进过详情就是空的。子目录挂在上次访问痕迹上，不挂在主目录上（这是用户说的「主目录/子目录混淆」的代码本体）。
3. `gradeInfo` 非空抢渲染年级详情；清理回执走 `tab === 'receipt'` 而 `receipt` **不在 tabs 数组里** → 进回执时页签条零高亮，随手一点就丢。
4. 全部层级共用 URL `/student` → 刷新/后退/分享全失效（项目里已有 `submit/settings` 子路由先例）。
5. 批量重置密码两套入口两套语义：`PUT /student/reset-password`（按 grade/classNo 范围）vs `POST /student/reset-password/batch`（按 ids）；另「导出本届」偷偷改写 `listQuery.grade`、`importResult` 切走再回来还挂着。

- 树：全部账号 / 在用年级（年级节点 → 班级子节点，2023 级带红点=可毕业清理）/ 已归档（2022 级 → 只读回执）/ 分隔线 / 名册导入 / 导入批次。
- URL：`/student`、`?grade=`、`?grade=&class=`、`/student/archive?grade=`、`/student/import`、`/student/batches`。
- 同时给出 **方案 B（轻量修正）**：保留 4 页签，只把年级详情/回执改 URL 驱动 + 班级下拉改级联；建议 A。

## 🐞 修 bug：管理端「改名」按钮点了没用（已修 + 已补回归）

用户报「改名的那个按钮改完之后没有实现目的」。

**根因（字段名对不上，静默 no-op）**
- 前端 `StudentAccounts.vue` 的 `submitRename` 发的是 `{ remark: x, nickname: x }`；
- 后端 `studentRosterService.updateStudent` 只读 `payload.name`（`patch.remark = payload.name`）；
- → 三个 key 全落空，接口照常回 200「已保存」，**姓名一个字都没动**。

**连带问题（就算把字段名对上，只写 remark 也不够）**
读姓名的地方不是一个，而且 `nickname` 优先：
| 读哪 | 读什么 |
|---|---|
| 管理端学生账号列表 | `remark`（dto 暴露成 `name`） |
| 管理端投稿审核 / 留言审核 | `nickname \|\| remark` |
| 小程序「我的」/ `/user/me` | `nickname \|\| remark` |
| 名册导入落库 | **两列一起写** |
所以改名必须 **`remark` 与 `nickname` 同时写**，否则管理端变了、学生端还是旧名。

**改了什么**
1. `src/services/studentRosterService.js` `updateStudent`：
   `name` / `remark` / `nickname` 三个 key 都接受（兼容旧调用方，杜绝再静默失败）；
   校验 trim 后非空（空 → 40001「姓名不能为空」）、≤64 字；**两列同时写**。
2. `admin-web/src/views/StudentAccounts.vue` `submitRename`：改发 `{ name }`，
   加空值/未变化短路，**用 try/catch 自己弹错误提示**（`utils/http.js` 的响应拦截器对
   `code!==0` 的业务错只 reject、**不弹 message**，只靠"拦截器已提示"会静默失败）。
   弹窗补上「账号 xxx · 班级」上下文 + 回车提交。
3. `scripts/verify-student-account.js` 新增 **G3 段 12 项断言**（原本这条路**一条覆盖都没有**，
   所以 bug 才能溜到线上）：name 落库、nickname 同步、列表搜得到、
   **学生端 `/user/me` 也是新名**、别名兼容、空名/超长拒绝、改状态不串字段。
   → `node scripts/verify-student-account.js` = **163 项通过 / 0 失败**。
4. `docs/student-account.md` 补「姓名的字段名」小节（读哪列的表 + 别名 + 回归位置）。

## 「重置不了学生密码」排查 + 修复（已落地，等陛下 push）
- **根因**：v3 的三处成功 toast 都写 `icon: IconKey`，但 `StudentAccounts.vue` 的 icons import 漏了 `IconKey`（图标库里本来就有 `icons/index.js:36`）。密码**其实重置成功了**（PUT/POST 都 200），但 toast 构造在 `icon: IconKey` 处 ReferenceError，被自家 `catch` 接住弹红字 **「IconKey is not defined」**——看起来就是「重置失败」。hero 批量那条更迷惑：try 块在 toast 处中断后 `fetchStudents()` 也不跑了，页面上毫无反馈。
- 修复：import 补 `IconKey`（一行）。验证（真实点击 + XHR hook）：行内 `PUT /student/1/reset-password → 200` + 深色 toast「已把 王子轩 的密码重置为 user20230101」；hero「重置这 62 个的密码」→ `GET list?pageSize=200（scopeIds 取全量 id）→ POST reset-password/batch → 200` + toast「已重置 62 个账号的密码为初始密码」→ 列表刷新。截图 `shots/student-v3/reset-01~02`，构建 8.05s 过。
- ⚠️ 教训（排查路径）：用户说「重置不了」时接口层先 curl 一遍（登录→list→重置），全通就说明坏在前端交互；XHR hook + 截图里的 toast 文案直接把根因写在脸上。另：`window.__log` 读回来时注意外层还有 run() 的 500 字符切片，会误判「请求没发」。
- ⚠️ 本机 `_shot.db` 验证库已被这轮测试打穿：hero 批量重置跑了两次，62 个账号 pwd 全部回初始态（「已激活 0」是重置的副作用，不是 bug）。
