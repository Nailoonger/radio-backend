4. **跨文档原子性放宽**：不依赖长事务，改为「单文档原子更新抢位 + 幂等键防重跑」（原事务里日志与主操作同生共死，此处放宽为审计日志允许失败）。
5. **数字主键保留**：`sequence` 集合 + `_.inc(1)` 生成 `id`，与旧数据同一 id 空间，避免前端/日志里的 id 语义漂移。

**⚠️⚠️ 本轮最有价值的两个发现（都是「不报错」的静默漂移）**

1. **`ApiError` 签名漂移 —— 数据被静默吞掉**
   源 `src/utils/response.js` 是 **4 参** `(code, message, httpStatus, data)`；
   云版一开始简化成 3 参 `(code, message, data)`。
   于是从 src **逐字复制**过来的 `songWindow.assertOpen`：
   `new ApiError(Codes.SONG_WINDOW_CLOSED, msg, 200, { opensAt, windowText })`
   → `200` 被当成 `data`，`{opensAt}` 被丢弃 → **前端拿不到倒计时，且 message 还是对的**，
   本地测试才暴露（`40907 带 opensAt` got=200）。
   **修法：把云版 ApiError 改回 4 参**（对齐源签名），而不是去改每个调用点 ——
   这类带 data 的拦截（窗口/满额/候补）在阶段 5、7 还会继续出现。
   ⚠️ 同步改了 `fail()`（原本 `new ApiError(code, message, data)`，改 4 参后会错位）。
   **教训：凡是「逐字移植」的模块，其依赖的签名也必须逐字对齐。**

2. **路由层中间件在移植 controller 时极易漏**
   Express 的鉴权挂在**路由**上（`router.get('/submit/window', userAuth, submit.windowStatus)`），
   而 controller 里**不读** `req.user`。只搬 controller 就会漏掉鉴权 ——
   漏了不报错，只会「未登录也能看」。
   本轮 `windowStatus` / `timeslots` 就是这样漏的（`notice`/`quota` 因为读了 `req.user` 才没漏）。
   **判据：必须对照 `src/routes/user.js` 逐个接口看有没有 `userAuth`，不能看 controller 有没有用 `req.user`。**
   ⇒ `/user/submit` 全组需登录，**唯一例外是 `/user/submit/week`**（源路由确实没挂）。
   已把这 5 条断言写进 `test-user-submit.js`（`window`/`timeslots`/`notice`/`ack` 未登录→40101，
   `week` 未登录→0），以后漏了会当场报红。
