## 学生端底部导航动效重写（动画契约 v11）

陛下反馈：切 tab 时指示器「抽搐一下」、有时不从原来那格滑到目标格、整体也在抖。

**根因（三条，全对得上症状）**
1. `wx.createAnimation` 同时动 `left%` / `width%` / `scaleY`，四段各自 ease-out：速度一段段急停，
   加上 scaleY 纵向挤压 ⇒ 抽搐。（**left/width 本身不是根因**，见补二，别拿它当理由再删拖尾）
2. 「先 0ms 落位、setData 回调里再播 400ms」两段式：0ms 那段在原生层没有帧，常没画出来，
   第二段就退化成「从元素当前样式（left:0＝第一格）起跳」⇒ 不从原位滑。
3. 滑动在**目标页 onShow** 里补演，点了之后要等 `wx.switchTab` 完成才动 ⇒「没反应→突然跳→再滑」。

**改法（`miniprogram/custom-tab-bar/`、`utils/tabMotion.js`、`app.wxss`）**
- 指示器位置用 `left`、拖尾用 `width`（两端弧度靠 `border-radius: 999rpx` 恒定）。
  **不是** translateX/scaleX —— 那样会把圆角拉扁，见补二。
- 12 组 `ind-<from><to>` 关键帧把起点写死，起点永远取自用户眼睛看到的那一格。
- 滑动在**点按那一刻**的当前实例上开演（每页各有实例，只有它此刻可信），只发一次 setData。
- 目标页 onShow 只做静态落位 `ind-rest-<n>`，正常路径连 setData 都不发。
- `pageLifetimes.hide` 把实例拨回本页格位（`selected` + `indicatorClass` 一起），
  否则复用的实例再出现会先闪一帧在上一格。
- 页面内容入场改成只淡不位移（0.78→1 / 200ms）：`.body` 上的 `transform` 会让它成为
  `position:fixed` 后代的包含块，`.sklayer`、弹层、底栏会跟着搬 ⇒ 整页抽搐。
- 图标微弹从 JS 打 `motionClass` 改成 `.tab.on .tab-icon-wrap` 纯 CSS 触发（两次 setData 会被合并，弹不出来）。

**判据/自检**
- `node _opfit/chk-tabbar-motion.cjs` ⇒ ALL OK（12 组关键帧起点/终点、拖尾四拍、
  指示器内**无 scaleX/scaleY/translateX**、switchTab 成功路径 1 次 setData、tabMotion 无 transform）。
- `node scripts/release/verify.js --scope mini` ⇒ exit 0。
- 同参数可点预览：`preview/tabbar-motion-v11/index.html`（含自动连点，用来看起点会不会错）。

**铁律追加**：一次切页只准一次 setData；起跳点必须写进关键帧，不许依赖"元素当前样式 + setData 时序"；
拖尾必须让两端保持标准半圆（只改 width，不碰 scaleX）。伙伴端 `partner-tabbar` 无动画，不涉及。

**补一：拖尾被删 → 先想用 scaleX 搬回（同日 00:50 陛下指出）**
- 他说「我的拖尾效果咋给我删掉了」—— 旧版 `flowing()` 的「前沿先冲、后沿滞后」拉伸是真需求，
  我为了避开重排把 width 拉伸整段删了，属于误伤。
- 改法：`translateX + scaleX`，纯合成层。四拍 `0% → 35%(拉长 1+0.62d 格) → 74%(追上，略撞过终点) → 100%`，
  每拍 ease-out（旧版手感，别合成一条连续缓动）。
- ⚠️ **`transform-origin` 必须跟方向切**：向右 `0 50%`（后沿在左）、向左 `100% 50%`。
  放错的话被拉长的那头变成后沿，拖尾整个反向（看着像先缩后伸）。
- 竖向挤压（旧版 scaleY 0.90→1.02）**没搬回来**：只在纵向抖一下、跟横向不同节奏，是抽搐来源之一。
- 切页压后 `SWITCH_DELAY = 0.71 × 240 ≈ 170ms`：不压后的话 `wx.switchTab` 一来页面就换，
  拖尾被砍在拉伸中途 = 刚拉长就归位，等于没有拖尾。
- 自检 `chk-tabbar-motion.cjs` 加了三项：起点/终点、**支点跟方向切**、**拖尾四拍与"后沿滞后"判据**。

**补二：scaleX 方案被否 —— 圆角被拉扁（同日 00:52 陛下给了对照图）**
- 症状：`scaleX` 连 `border-radius` 一起横向缩放，拉伸时两端从半圆变成被压扁的椭圆尖，很难看。
- 正确形态（他给的参照）：**拉长时两端弧度不变，永远是标准半圆**，像一根被拉长的胶囊。
- ⇒ 只能用真实 `width` 变化（`border-radius: 999rpx` 被 clamp 到高度的一半，宽度怎么变两端都圆）。
- 最终 12 组关键帧改成 `left` + `width`（%）：35% 前沿冲 68% / 后沿滞后 6% / 宽 1+0.62d；
  74% 宽 1+0.06d、前沿略过终点 1%。`transform-origin` 不再需要（没有 scale 了）。
- 代价：left/width 每帧重排。对象是绝对定位、无后代、无文字的纯色块，可接受；
  抽搐真因（两段 setData + 纵向挤压 + 错位补演）已全部消除，**别再拿"重排"当理由砍掉拖尾**。

**补三：接线收口（同日 00:57 落地）**
- `switchTab(e)` 只取格位，转给新方法 `go(index)`；`go` 是唯一入口。
- 页面内的按钮改走 `getTabBar().go(n)`：首页「立即投稿」→ `go(1)`、投稿页「去我的投稿」→ `go(3)`。
  直接 `wx.switchTab` 的话底栏不演拖尾（`tabFrom` 得手写、容易写错格），观感与点底栏不一致。
  其余 15 处 `wx.switchTab` 都在非 tab 页（详情/登录/公告），没有底栏在屏上，不用改。
- ⚠️ 修一处语义 bug：`_own` 曾在 `go()` 里被设成**目标格**，而 `hide()` 拿它当"本页格位"复位
  ⇒ 复位到目标格，下次本页首帧就闪错位。改成 `_pageIndex`，只在 `setSelected` 写。
- `index.js#setTabBar` 加了 diff 守卫：值没变就不发 setData（onShow 每次都调它）。
