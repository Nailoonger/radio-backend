### ③ `unlock` 落地（本轮主要工作量）

**核心洞察**：解锁不能只把 `status` 改回 `SCHEDULING` ——
`sweep()` 的自动锁定判据只有 `now >= schedule_lock_at`，而解锁**必然发生在锁定时刻之后**，
不拦住的话下一轮 sweep 立刻把它锁回去，**解锁等于没做**。
所以新增 `weekly_schedule.lock_paused TINYINT`（1 = 暂停本周自动锁定）。

改动：
- `src/models/weeklySchedule.js`：新增 `lockPaused`（`lock_paused`）。
- `src/services/songSchedulingService.js`：
  - `unlockWeek(weekStartMs, { now, operatorId, restore })` —— ①退回 `SCHEDULING` + 清 `lockedAt`
    ②恢复锁定时被系统自动驳回的候补（只动 `schedule_status=AUTO_REJECTED` 且 `auto_rejected=1`
    且 `review_status=APPROVED` 且驳回理由 = `lockedNoSlot` 的；`restore:false` 可跳过）
    ③`lockPaused=1`。未锁定的周抛 40001。
  - `lockWeek()` 成功时 `lockPaused: 0`。
  - `sweep()` 新增分支：`lockAt && now >= lockAt && lockPaused===1` → **跳过锁定**，只跑排期补空位，
    `entry.lockPaused = true`。
  - `weekView()` 下发 `lockPaused` / `unlockable`。
- `src/controllers/admin/submitController.js`：`exports.unlock`（文案带恢复条数）。
- `src/routes/admin.js`：`POST /submit/schedule/unlock`（`requireSuperAdmin`，字面量段在 `/:id` 前）。
- `admin-web/src/views/SubmitList.vue`：`week.locked` 时「锁定本周」→「解锁本周」（带影响说明二次确认）；
  `week.lockPaused` 时状态行/大字/hint 三处显示「自动锁定已暂停」；新增 `unlocking` ref + `unlockWeek()`。

### skill 修正：`web-ui-screenshot-verify`

本轮被工具坑了一整轮，四条已写入 skill：
1. ⚠️ **`eval` 返回值是带引号的 JSON 串** → `info.indexOf('x') === 0` 永远为假，
   现象是「eval 打印了结果但后续截图静默不执行」。判据一律 `>= 0`。
2. 按文案找元素别用全等（本项目链接文案带尾巴 `看排期矩阵 ›`）。
3. 用 `querySelectorAll('*')` 筛叶子节点会**命中 `<style>`**（其 textContent 就是整段 CSS）。
4. **`document.body.className` 为空 ≠ 页面死了**：admin-web 的 body 本来没 class，
   skill 原判据会假报空白页（实际截图 150KB 内容完整）。
   新增「量 `getBoundingClientRect().height` 判折行」的配方。
