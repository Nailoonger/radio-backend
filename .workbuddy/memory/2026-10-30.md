## 审核页「通过 / 驳回」胶囊被拉成半屏宽（00:5x）
陛下截图：审核页（点歌）待审行底部的两个 `.sm2` 胶囊变成**两条占满整行一半宽**的灰长条、文字居中。

### 量出来的
截图是整屏宽 607px（= 750rpx，1rpx = 0.809px）：
- 胶囊高 46px / 0.809 = **57rpx** ⇒ 正是 `.sm2` 的 `17rpx*2 内边距 + 23rpx 字号` ✅ 说明 `.sm2` 生效了
- 胶囊宽 255px / 0.809 = **315rpx**，而行内可用宽度 (618-12)/2 = **303rpx** ⇒ **正好等于「半行」**
  ⇒ 两个按钮各自被撑到 100% 再对半缩，文字居中（button 默认居中）

### 根因
**微信内置的 `button` 样式优先级高于单个类名，会把按钮撑满整行**（app.wxss 里 `button.btn`
当初就留了这条注释：必须用元素+类选择器 + 显式 `width: auto` 才压得回去）。
`button.sm2` 是元素+类、颜色圆角都对，**唯独没写 `width`** ⇒ 沿用内置的撑满宽度，
两个挤在一行就各缩一半。所以看起来「胶囊位置不对」，其实是宽度被吃掉了。

### 修
`review.wxss` / `leave.wxss` 两处 `button.sm2` 补 `display: block; width: auto; min-width: 0; box-sizing: border-box`；
`.r-act` 从 `flex-basis: 100%` 改成 `flex: 0 0 100% + width: 100%`。
⚠️ 两个文件是**同一个类的两份副本**（审核页 / 请假页），改一处不算改完。
⚠️ 铁律升级：**凡是给 `<button>` 定尺寸，除了 `flex`，一定要显式写 `width: auto`（或具体宽）**，
只写 `flex: none` 会被内置样式吃掉。

### 3. 「代录完再次生成班表没效果」的两个真原因
- ① **两边不是同一周**：代录页能翻到下一周，排班工作台原来写死只排本周（`/partner/schedule` 不带 week）
  ⇒ 工作台加周切换；`goProxy()` 把 `week` + `base` 一起带给代录页（否则代录页永远打开本周）
- ② **静默 no-op**：`mutate()` 在 `busy / loading / loadError` 时 `return Promise.resolve(null)`，
  **一个字都不提示** ⇒ 弹窗确认后请求根本没发，表现就是「点了没反应」。已改成明确 toast
- ⚠️ 后端逻辑本身是对的：用 harness 真 handler 复现过「代录把某人改成不能来 → 再次生成会换人」。
  以后遇到「生成了没变化」，先问 **是不是同一周 / 是不是全是 fixed 人**（generate 只保留固定人选重排其余）
- ⚠️ `generate` 只保留 `fixed` 的人选，其余重排；若整周都是手工填的（`setCell` 默认 `fixed:true`），
  「再次生成」结果必然一样 —— 这不是 bug，是设计；要全重来用「一键清空班表」

### 追加：配岗位弹层必须同时配「部门」（commit `e7a9c04`）
- **现象**：配完角色，换人弹层还报「尚未配置部门与岗位资格 / 部门不匹配」
- **根因**：`reasonsFor()` 里部门与岗位是**两条独立硬条件**：
  `if (!person.department || !person.dutyRoles.length)` 一条糊住两件事，
  `if (def.dept && person.department !== def.dept)` 又是一条 —— 部门空的时候两句同时命中。
  而上一版「配岗位」弹层只写 `dutyRoles`，**全站没有任何配部门的入口**（admin 表有字段、界面没有）
- **修**：弹层加部门单选（再点取消）+ 后端 `saveDutyFor` 接受 `department`（不传＝保持、空串＝清空）；
  超管自己的卡片也显示「配岗位」；空部门 + 有岗位时保存先弹一次提醒；
  「我的值班角色」卡在没部门时直接提示去找超管
- ⚠️ **合并提示的坑**：一句话里塞两个条件（「尚未配置部门与岗位资格」）= 用户不知道该补哪个。
  **报错要拆开、并且带出双方的值**（「部门不匹配（当前：主持部，这个时段要：播音部）」）。
  改了文案记得同步 `test-partner-schedule-v151.js:83` 那条精确匹配断言

### 再追加：一个维度就够了 —— 只配「部门」，岗位由后端推导
- **陛下原话**（拿两张截图问区别）：「你直接给我做一个就好了，**我配置完部门之后就可以了其他的不要了**」
- 上一版弹层里「部门 + 值班岗位（多选）」两行并列 —— **同一件事让用户选两遍**，
  而且两处不一致就选不上人（后端 `reasonsFor` 部门与岗位是两条门槛）。
- **改法**：岗位不再让人选，由 `me.js#ROLE_BY_DEPT` 按部门自动带
  （播音部→播音 / 主持部→主持 / 编辑部→编辑），**库里已有的记者 / 技术原样保留**
  （`body.dutyRoles === undefined` 时推导；显式传 `dutyRoles` 仍按显式的走，兼容旧调用）。
- 两处入口一起收口：① 人员卡片「配岗位」→ 改名「**配部门**」，弹层只剩一组部门单选
  ② 页面顶部自助卡「我的值班角色」→「**我的值班部门**」，同样单选
  ⇒ 两处都是 `{ department }` 一个字段，一个来源，不可能对不上。
- 清掉的自创/死代码：`ROLE_OPTIONS`、`roleChips`、`rolePicked`、`_extraRoles`、
  `roleTargetChips`、`_targetRoleExtra`、`onToggleRole`、`onToggleTargetRole`。
  ⚠️ 模板与 JS 必须同步改 —— JS 换成 `deptChips` 后 WXML 还 `wx:for="{{roleChips}}"`，
  渲染出来是**空卡**（不报错，只是三个格子不见了）。改字段名一律 `grep` 全目录确认零残留。
- 判据：duty **253** · schedule-v151 668 · isolation 57 · regression --source **2100 项 0 失败** ·
  sync 70 模块 600.0 KB · verify mini **pass 53 fail 0** · 临时 vm 自检 34/0
  （自助卡单选/再点取消/保存只发 department/没拉到不许保存 + 弹层单选/清空二次确认/非超管打不开）。
- ⚠️ **写 vm 自检时踩的坑**：`adminRequest` 的真签名是 `adminRequest(url, method, data)`，
  **url 在第一个参数**。我先按 `(method, url, body)` mock，结果 10 条断言全红、
  看起来像业务写坏了 —— 是**探针错**不是代码错。写探针前先 `grep` 一次函数签名。

### 第三版定稿：改回「配岗位」，且可多选（推翻上一版的「只配部门」）
