## 通知收发模块 · 方案 + 静态预览 v1（待批）

**需求**：老师通知社团学生到某地开会 / 社团负责人通知成员开会活动。学生端要有入口，
进去不登录、凭后台分配的通行码；伙伴端仅社干/超管可发。

**我的判断（否掉"长期通行码"）**：
- 长期通行码＝免密登录，泄露一次就等于把该社团全部通知给出去，要防冒充就得再绑设备/手机号，反而更重。
- 改成 **一条通知一个 6 位通告码**：泄露只泄露这一条，72h 失效。
- 身份不靠密码：发通知时绑定部门/社团 ⇒ 学生进来直接在名册里点自己，零输入、不可冒充（一人只回执一次）。
- 比输码更强的一步：**直接转发通知本身**（小程序分享带参），点开免输码；码只留给口头/黑板场景。

**产出**：`preview/notice-hub-v1/`（index.html 屏幕墙 + app.html 逐屏，10 屏）
- 学生端 5：首页入口（免登录）· 输通告码 · 通告单详情 · 名册点自己 · 回执完成
- 伙伴端 5：通知列表 · 发起通知 · 通行码页 · 回执看板 · 通知详情
- 业务隐喻：通告单（No. 编号 + 签发 + 钢印）+ 调频数字码；无深色面板；沿用 v8 token。

**技术落点（未写业务代码）**：
- 免登录接口照 `handlers/user/recruitment.js` 的做法：不进 userAuth，只用 `rate()` 限流（招新查询码已有先例）。
- 新表：`notice`（码、绑定部门、正文、时间地点、需回执、截止、状态）、`notice_receipt`（notice_id、user_id 或手填姓名、回执时间；唯一键防重复）。

## 通知收发 v1 方向错了 → v2 重做（同日）

**陛下原话纠正**：「这个模块是针对各个社团和老师需要**播送**通知开发的……社干和超管在后台就可以看见内容，
审核通过以后，进入待播，播送完之后点已播出，某社团社长就可以收到反馈已经播送，他可以查看自己的通知走到哪一步了，
**不需要做成员确认只是一个通知收发的而已**。」

**我 v1 错在哪**：做成了「给个人发通知 + 点名回执」——名册点选、回执统计、一通知一码，全是学生侧到人的送达。
真实业务是**播送申请工单**：社团→广播站→播出，全程只有「这条稿子」在流转，没有「谁收到了」。

**v2 口径（`preview/notice-hub-v2/`，10 屏）**
- 状态机：`待审核 → 待播 → 已播出`，旁支 `已驳回`（必填理由，可改后重提）、`已撤回`。
- 通行码是**社团级长期码**（6 位，后台分配、可重置，换人换码旧码作废）——不是一通知一码。
- 提报方（社长 / 老师）：输码 → 社团通知台（我们提过的 N 条 + 状态）→ 提报表单 → 进度页（四节点时间线）。
- 审核方（社干 / 超管）：审核队列（待审核/待播/已播出三段）→ 审核台（正文 + 字数 + 口播时长 + 排播时段 + 播几遍）→ 待播页「标记已播出」。
- 两个关键设计：**200 字上限**（口播约 50 秒，时段有限，逼提报方写短）；**按 4 字/秒自动算口播时长**显示给审核方。
- 提报方填「希望播出时段」，实际排播由社干定（审核台并排显示"社团希望 / 排到"）。

**教训（写进铁律）**：需求里出现「通知」两个字，先分清是**送达类**（发给谁、谁看没看）还是**播送类**（一条稿子走审批）。
看到「通行码」不要立刻推成"一通知一码"，先问这个码代表的是"一次投递"还是"一个组织身份"。

### 旋转观感再调：圆环走位 + 每枚按角度自转（11-06 22:05）
陛下：「旋转的效果要上一版的样子啊」——真圆环（整体 rotateY）时侧位被压成扁椭圆，他不认；他要的是
**上一版那种"中间大、两侧小一圈、稍微后仰"的观感**，同时保留圆环转动、背面看不到。
- 定稿做法：**不给 stage 整体旋转**，每枚自己算位置——
  `t=(k-step)*A`（A=60°）→ 归一到 -180~180 → `x=sin(t)*R`、`z=cos(t)*R-R`、
  `rotateY(t*0.42)`（只自转四成 ⇒ 正面全平、侧位约 25°）、`scale(max(.72, 1-|t|/90*.30))`、
  `opacity = |t|<90 ? 1 : 0`。R=136。
- ⚠️ **必踩的坑**：`t` 不做 -180~180 归一，k=4/5 会算成 240°/300°，`|t|>90` 全被判成"背面" ⇒
  只剩 2 枚可见、整个轮播偏右。归一后左右才对称。
- 结果：同时看到 3 枚（0° / ±60°），±120° 与 180° 不可见；方向恒定（右侧进来→中间→左侧消失），
  不会出现"从左滑到右"。

### 「还是从左飘到右」真凶：resume 过渡的时机（11-06 22:30）
陛下第二次报同一个问题。30ms 采样探针实测（`maxRightMove`）确认：
**rAF 里恢复 transition 会早于本帧样式计算** ⇒ 屏外 park 那一下"瞬移"被补间成横穿屏幕。
- 修法：**强制回流**再恢复，不用 rAF：
  `el.style.transition='none'` → 设 transform/opacity → `void el.offsetWidth;` → `el.style.transition='';`
- 同一坑还在**首帧落位**：`.car.no-tr` → layout() → 双 rAF 去掉类，也会把"从中心散开"补间成一次乱飞
  ⇒ 同样改成 `void box.offsetWidth; box.className='car';`（同步）。
- `goTo()` 顺带改成走**最近一侧**（`if(d>N/2)d-=N`），避免点圆点时一次扫过半个圆。
- 探针（30ms×11s）结果：可见状态下向右位移 **0.0px**。
- ⚠️ 提醒陛下用带 `?v=` 的链接刷新，静态托管会缓存旧 HTML —— "还是老样子"有时候是没拿到新包。
