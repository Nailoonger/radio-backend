## 关键拍板（与原型一致，写进代码注释了）
- **密钥只存哈希 + 掩码**：`key_hash = sha256(pepper:明文)`、`key_mask = '····M7'`；
  明文只在 `POST /partner/club-keys/:id/reset` 的返回里出现一次。
- **不走 bcrypt**：校验时服务端不知道是哪个社团，bcrypt 要全表逐个比（N × 25ms）；
  sha256 可以拿哈希直接等值查一条。pepper 取 `CLUB_KEY_PEPPER`，没配由 `JWT_SECRET` 派生。
- **字符集去掉 `0/O/1/I/L`**（`ABCDEFGHJKMNPQRSTUVWXYZ23456789`，6 位）：密钥要照着念/手抄。
- **学生票 2 小时**：输对一次换 ticket，库里只存 ticket 的 sha256。重置密钥**不**踢掉已发的票
  （重置是给「新人别再用旧钥匙」，不是把正在提报的在校生赶出去）。
- **作废必须清哈希**：只改 status 就是假作废（列表显示已作废、旧钥匙照样能进）。
- **头像只能换自己那家**：社团 id 取自票据，**接口不读前端传的 clubId**。

# 补丁 · 线上 -502005（push 之后第一下就炸）

## 现象
陛下截图：密钥页弹「服务器繁忙，请稍后再试（collection.get:fail -502005 database collection not exists.
[ResourceNotFound] D）」。此时 `origin/master` 已同步（他已 push、CI 已发），所以跑的就是本批代码。

## 根因（三层，缺一层都不会炸）
1. 云开发查**没建过**的集合是**抛错**，不是返回空数组。
2. `ensureSeeded` 里的 `try { createCollection } catch {}` 把建表失败**静默吞掉**（无权限 / SDK 差异时）。
3. 紧接着的 `findMany` / `findOne` 是裸调用 ⇒ `-502005` 原样抛到前端。
   `list()` / `publicList()` / `mustRow()` / `readSession()` / `guardTry()` 都是裸的。
   假库对任何集合名都「返回空」⇒ 本地永远测不出这条路径。

## 修法
- `lib/db.js` 新增 **`ensureCollection` / `ensureCollections`**：幂等、每实例只试一次（memo）、
  已存在当成功、**失败不抛**（返回 `{status:'error'}`，删掉 memo 下次再试）。
- `clubKey`：`ensureTables()` = 建三张表，进 `ensureSeeded / issueSession / guardTry` 先调；
  `list/publicList/mustRow/readSession/guardTry` 的读全部套 `readOr`（当空表）。
- `clubNotice`：`ready()` 建单据表，`create/myList/one/queue/findRow` 都先调 + `readOr`。
- `guardTry` 的「并发退化成 update」也可能再失败（表没建）⇒ 再包一层 try：
  **限速记不下来不该把一次正常验码变成 50001**。

## 测试（这条最关键）
- `harness.js` 新增 `dropCollection(name)`：把表当作云上没建（读它就抛 -502005），
  并**清掉云函数模块缓存**（模拟冷启动，否则 `ensureCollections` 的 memo 会说"建过了"）。
  `reset()` 会 `dropped.clear()`。
- `test-club-key` ⑪：删三张表后 → 列表 5 家 / 深链直接重置 / 出票 / 错码 40401 / 轮播清单 —— 全不 50001。
- `test-club-notice` ⑮：删单据表后 → 提报 0 / 我的提交 / 处理台队列 —— 全不 50001。
- 断言：密钥 80 → **88**、提报 85 → **91**、全量两轮 **4920 项 / 0 失败**；`verify --scope mini` exit=0。

## 教训
**「本地全绿」要有意义，假库必须能模拟真库的失败模式。** 之前假库对未建集合返回空，
等于替代码兜了底 —— 所有「首次使用 / 升级后第一次」的路径都没被测过。

# 补丁 2 · 这个模块**不登录也要能用**（陛下当面纠正）

## 我错在哪
入口在「我的 → 广播通知」对未登录也显示了，但后端 8 个接口全挂 `requireUser`。
未登录学生一进输码页、一按「进入」就被 40101 踢去登录 —— 与「不登录也能用这个模块」完全相反。
根因是照搬了别的线的写法：把「学生账号」和「社团钥匙」两件无关的事绑在一起。

## 改法
- `handlers/user/clubKey.js`：`verify` / `me` / `avatar` 去掉 `requireUser`。
  试错闸来源改用 `ctx.source || cloud:${ctx.openid}`（平台注入，没登录也有），**不按登录用户限速**。
- `handlers/user/clubNotice.js`：5 个接口全去掉 `requireUser`，只留票据一道闸；
  新增 `optionalUser()` —— **有 token 就用学号当落款，没有就退「社长」**（token 过期也不拦）。
- `services/clubNotice.create`：落款兜底 `club.owner_name || 学号 || '社长'`（原来空串，伙伴端会看到空白）。

## 连带修的坑：40102
票据失效原来报 **40101**，而 `utils/request.js` 一看到 40101 就**清本地登录态** ——
学生用社团密钥提报一次、票据两小时一过期，就把自己的小程序登录弄没了。
新增 `Codes.TICKET_EXPIRED = 40102`，文案「社团密钥已过期，请重新输入」；
`needClub` / `avatar` 改抛它；前端 4 处判断改成 `40102 || 40101`（兼容旧部署）。

## 验收
- 密钥 88 → **90 项**、提报 91 → **93 项**，全量两轮 **4928 项 / 0 失败**；`verify --scope mini` exit=0。
- 新钉的断言：「没登录也能验并出票」「没登录凭票据照样认社团」「有票据、没登录照样能提报」
  「撤回不要求登录」「落款退到社长」。这五条是**反面记录** —— 别再有人加回 `requireUser`。
