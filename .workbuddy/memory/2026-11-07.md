## 关键拍板（与原型一致，写进代码注释了）
- **密钥只存哈希 + 掩码**：`key_hash = sha256(pepper:明文)`、`key_mask = '····M7'`；
  明文只在 `POST /partner/club-keys/:id/reset` 的返回里出现一次。
- **不走 bcrypt**：校验时服务端不知道是哪个社团，bcrypt 要全表逐个比（N × 25ms）；
  sha256 可以拿哈希直接等值查一条。pepper 取 `CLUB_KEY_PEPPER`，没配由 `JWT_SECRET` 派生。
- **字符集去掉 `0/O/1/I/L`**（`ABCDEFGHJKMNPQRSTUVWXYZ23456789`，6 位）：密钥要照着念/手抄。
- **学生票 2 小时**：输对一次换 ticket，库里只存 ticket 的 sha256。重置密钥**不**踢掉已发的票
  （重置是给「新人别再用旧钥匙」，不是把正在提报的在校生赶出去）。
- **作废必须清哈希**：只改 status 就是假作废（列表显示已作废、旧钥匙照样能进）。
- **头像只能换自己那家**：社团 id 取自票据，**接口不读前端传的 clubId**。

## 踩坑
- 试错闸状态必须落库：云函数无状态、多实例冷启动各算各的，内存计数等于没有。
  一份来源一个文档（`_id = <source>`，只存 `{minute,count}`），不随分钟数增长，不需要清理任务。
- 种子用 `_id = 'club:<社团名>'`：两个请求同时发现表空会各插一遍，自动 `_id` 挡不住重复
  ⇒ 轮播里出现两个「电视台」。
- 测试最后一行必须是 `结论：断言 N 项 / 失败 0 项`，否则 `regression.js` 判「无结论行」= 未全绿。

## 关键拍板
- **标题不让学生填**：原型只有三栏，加标题＝同一件事写两遍 ⇒ 由正文派生（首 20 字，[8,20) 有分句标点就在那儿收），伙伴端审核时可改。
- **审核位复用 `review`**：对站里来说「通知能不能上」和「稿件能不能上」是同一件事，多一个开关只是多一处会忘记开。
- **通过不强制排期**：课间先审完、下午排播再补是常态，强制必填会让社干十分钟课间审不动一条。
- **时间线不另起流水表**：四步全从 create/review/air 三个时刻推出来，单独存一份必然与主记录分叉。
- **`/my` 必须排在 `/:id` 之前**：段数相同，只靠顺序区分。
