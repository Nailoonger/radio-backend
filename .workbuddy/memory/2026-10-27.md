```
PUT    /partner/slots/draft            存草稿（仅超管）

DELETE /partner/availability           撤销（只能撤自己填的或自己代录的）
```

### 关键设计决策（后续别推翻）
- **`asPartner` 是 async**：要多查一次 admin 文档拿资格字段，且**每次请求都校验 status**（JWT 7 天有效，只靠 token 会留一周空窗）。
- **能力位由后端给**（`abilities`），前端不自己从 `role` 推 —— 前端推错是越权入口，后端推错还有 `asSuperPartner` 兜底。
- **时段用版本表不用单条配置**：班表发布要把「当时的时段」钉死，否则改 10 月时段会让 9 月已发布班表的历史失真。状态机 `无草稿 → draft → published`，下次存草稿 version = 历史最大 + 1。**空草稿允许存**（配置到一半退出是常态），但**空草稿不能发布**。
- **`slotKey = <day>-<seq>`**，seq 只对某个时段版本有意义 → 存 picks 时记 `slotVersion`，读时版本不一致标 `stale:true` 让前端提示重填。**不静默丢弃站员填过的东西**。
- **人员池 = admin 表 status=1，`personId = admin.id`**。staff 表是官网展示用（有 avatar/motto/sort），不代表有登录账号，混进来会产生「排了班但人永远填不了时间」的僵尸岗。将来要纳入 staff，只改 `_kit.personKey/resolvePerson`，不动接口签名。
- **代录必须留原因（≥2字）且写 `duty_logs`**，否则事后无法区分本人填的和社干代填的。
- **「有不能来的时段必须填说明」放后端校验**，不只在前端 required —— 绕过前端就能写进空说明，而这类数据事后无法补救。

## 前后端接口对齐机制（23:10 起，陛下问「你知道吗」→ 直接做出来）

**背景**：前后端是两套独立代码，`adminRequest('/x')` 和 `router.js` 里的 `'METHOD /x'` 都是裸字符串，

**落地三件套**：
1. `cloud/contracts/partner.js` —— 契约（单一事实源），11 个接口的 req/resp 形状。

2. `cloud/scripts/check-contract.js` —— 静态：扫 50 处前端调用点 ↔ 163 条路由。

3. `cloud/scripts/verify-contract.js` —— 运行时：harness 内存库 + **真 handler** 跑一条业务流，
