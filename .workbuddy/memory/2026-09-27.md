## 推送：代理隧道「首次建立」慢 —— 先 curl 预热再推（订正 2026-09-24 旧结论）

今天推 3 个提交，一共试了 7 次：**5 次被杀（timeout 90/100/120/180 全 124、零输出），2 次成功（16 秒 / 2 秒）**。
成功的那两次之前**都跑过 `curl -x 127.0.0.1:7890 …/info/refs?service=git-receive-pack`**。

- 代理与通道都正常：`curl -x … https://github.com/` → 200；receive-pack → 401。
- **零输出 ≠ 卡在凭据**：`GIT_TRACE_CURL=1` 显示 `CONNECT 隧道 established, response 200` → 正常传 → 正常 `unpack ok`。
  纯粹是**慢**（隧道闲置后首次建立要等）。
- **凭据正常**：`GCM_TRACE=1 GCM_CREDENTIAL_STORE=wincredman git credential fill` **0.05 秒**返回
  `username=Nailoonger` + `gho_…`；日志 `Existing credential found` → `Writing credentials to output`。
  旧记忆「卡在 UI/COM 初始化、停在 `Arguments: get`」**今天不成立**。
- **可用配方**：先 curl 预热 receive-pack，再 `timeout 180 git -c credential.guiPrompt=false -c credential.interactive=never push --progress origin master`。
- ⚠️ **判据教训**：`git push … | tail -8` 把退出码换成 tail 的、进度全吞 → 我一度报"成功"，
  其实 `git status -sb` 是 **`ahead 2`**。**唯一可信判据 = `ahead N`，N=0 才算上去了。**
