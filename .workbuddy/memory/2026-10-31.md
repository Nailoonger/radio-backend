## 大白卡圆点渲染成大蓝球（00:2x）
- 陛下截图：「你这做的啥怎么那么大个」—— 轮播圆点的选中态成了一颗大蓝球，旁边灰点正常。
- 根因（**已用 headless Chrome 复现并量出像素，不是猜的**）：`desk.wxss` 的 `.dots .d` 把点击区和可见点
  画在同一个盒子上 —— `padding:15rpx 0` + `box-sizing:content-box` + `background-clip:content-box`，
  靠内圆角把背景裁成 13×13rpx 的小点。灰点时宽高相等，内圆角算得出来所以看不出问题；
  选中态 `width` 一放到 35rpx，内圆角失效、背景铺满 border-box（**35×43rpx**）⇒ 大蓝球。
  量值：改前蓝 17.5×21.5px / 灰 6.5×6.5px；改后蓝 17.5×6.5px / 灰 6.5×6.5px（原型 18×7 / 7×7）。
- 修法：照原型 `.dots > button > i` 的结构拆两层 —— 外层 `.dot` 只管点击区 `padding:15rpx 10rpx`，
  可见点在内层 `.dot-i`（宽高圆角底色 + `transition: width`），`.dot-i.on{width:35rpx}`。
- ⚠️ 铁律：**可见图形别画在带 padding 的盒子上**（`background-clip: content-box` 那套 hack
  只在宽高相等时成立；一旦某个状态改了宽度就崩）。尺寸要落在专门的内层元素上。
- 守卫加 4 条：圆点必须两层结构 / `.dot-i` 13rpx×13rpx / `.dot-i.on` 35rpx / **wxss 里不许再出现 background-clip**。
- 判据：`verify --scope mini` exit 0（54 段，守卫 30 条）· `node --test scripts/release/*.test.js` 53/0
  · WXML 配对未闭合 0 / 错配 0。
- 预览 `preview/desk-dots-fix-v1/`（before.png / after.png 都是真实渲染截图 + 量值表）。
